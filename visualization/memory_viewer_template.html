    数据来源与读法
    
    
      
  • 主实验来自 combined_work1000/：lossless_encoding_v1/（13 个纯文件系统家族）与 mixed_tool_expansion/（37 个文件系统 + Twitter / Math / Message / Ticket 家族），各 4 种条件 × 3 个新种子，共 600 条 Identity，其中 417 条触发转换。本地 Qwen3.8-27B-Q8_0，temperature 0.6。
    • 
      
  • 触发规则：工作输入（完整输入减去固定的系统 / 工具模板）严格大于 1000 tokens，且所有调用都已配对返回。7 个分支共用同一段 Identity 前缀；图分支在触发的那次调用前把历史替换成图一次，图之后不再更新，新的交互以原始消息追加。
    • 
      
  • 原格式与优化编码是同一份语义图的两种文本编码；图视图显示的是实际交付的图（memory-metadata.json），节点按其中记录的观察步号逐步出现。Event Graph 的两个版本还换了图说明（完整 151 → 精简 32 tokens）。
    • 
      
  • 环境：用 BFCL 官方执行器（同样的调用字符串转换与执行）逐条重放所有涉及的工具类，每次输出与记录一致，每轮结束时的目录树与 BFCL 状态日志一致。密码类字段在页面上隐藏。
    • 
      
  • 输入构成：工具定义与系统模板来自 accounting.json 的 fixed_tokens；图说明与图记忆正文来自交付记录；其余为对话历史与协议包装。
    • 
      
  • 同一条件、同一方法的成败在不同种子间常常不同；单个种子上的差异不能当作方法效果。早期实验（首轮后转换、history1000 旧口径）保留在“实验”菜单里。
